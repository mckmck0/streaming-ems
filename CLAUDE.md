# EMS: counterfactual multi-strategy energy management on durable stateful actors

<!-- Maintainers: keep this file under 200 lines and free of anything Claude can read from the code.

MSc thesis. An energy management system for residential prosumers (PV + home battery + grid, Polish/EU
market, 15-minute intervals) built on Restate Virtual Objects (Python SDK). The same live stream feeds N
strategies, each on its own virtual battery (counterfactual evaluation); one live strategy drives the
real battery and a Selector actor picks it. Exactly-once settlement under failures; hundreds of households.

Canonical docs: [docs/context/README.md](docs/context/README.md) (index). The status of every piece
(built, documented only, open) is in `docs/context/00-overview.md`. Do not @-import docs here.

## Orientation: before planning or writing anything

   experiments, infra, helm, docs.
2. **Ground**: invoke the `ems-context` skill and read only the `docs/context/` files it points to.
3. **Layer**: add the surface skill for the work (table below).

**Precedence when sources disagree:** this file and `docs/context/07-design-principles.md` → other
`docs/context/` files → skills and rules → `docs/bootstrap/PROJECT_CONTEXT.md` (frozen brief) → auto memory.

## Spec-driven workflow

- No feature code without an approved spec, plan and task list in `specs/NNN-feature/`; every change
  traces to a task. Only typo, comment, formatting and behaviour-neutral doc fixes are exempt.
- Entry point: `ems-plan-change`. It runs the principle, contract and risk checklists, then drives
  Spec Kit: `/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-analyze`.
- Stop for human approval after each phase. Never start implementation yourself: the user types
  `/speckit-implement`; afterwards run `/speckit-converge` until it reports converged.
- Acceptance criteria use EARS ("WHEN …, THE SYSTEM SHALL …"). Every plan that touches actors has an
  **Actor contract** section (template in `ems-actor-contract`).
- Spec Kit v1.1.0 is initialised (setup and upgrade steps: `docs/context/10-planning-guide.md`). Specs are
  written as we go, one piece at a time; the backlog order is in `docs/context/00-overview.md`.

## Commands

The `Makefile` is the only entry point. It holds only the targets the repo can use today; planned ones
(test tiers, `up`/`down`/`register`, `dev`, `exp`, kind and Helm) sit commented out at its bottom, grouped
by the spec that enables them. Enable a block with its spec, never ad hoc.

| Command | Purpose |
|---|---|
| `make install` | `uv sync` all groups + pre-commit hooks |
| `make format` | `ruff check --fix` + `ruff format`. **Run at the end of every code change.** |
| `make lint` / `make type-check` | `uv lock --check` + ruff check + format check / `ty check` |
| `make test-unit` / `make test-integration` / `make ci` | unit+property / against `make up` / lint + type-check + test-unit |
| `make up` / `make down` / `make topics` | Kafka stack (`infra/docker-compose.yml`) / stop / ensure topics (`PROFILE=`) |
| `make gen-backfill DAYS=2` / `make validate` / `make tail TOPIC=` | backfill to Kafka (sim profile) / validate topics / inspect |
| `make clean` | Remove caches and build artefacts |

Dev tools come from the `dev` group in `pyproject.toml` (ruff and ty pinned exactly; the ruff pin must equal
the ruff-pre-commit `rev`). `[tool.uv] exclude-newer` keeps every locked version at least two weeks old.

The PostToolUse hook in `.claude/settings.json` formats each `.py` file you edit and flags Restate imports
in `src/ems/domain/`. It does not see edits made through Bash, hence `make format`.

## Invariants (full text and checks: `docs/context/07-design-principles.md`)

1. Spec first: approved spec, plan and tasks before feature code; every change traces to a task.
2. Pure domain, thin actors: deterministic domain core; actors parse, delegate, write their own state, send.
3. Single writer per fact (ownership table in `docs/context/01-architecture.md`).
4. No blocking cycles: cycles only over one-way messages; request-response only to shared handlers (R1, R2).
5. Async-first handlers: blocking, CPU-heavy or non-deterministic work is journaled (`ctx.run`) and offloaded.
6. Exactly-once by construction: idempotent ingress, journaled effects, bit-exact check vs the offline reference.
7. Two clocks: experiments run on simulated time; wall-clock timers only in live mode.
8. Safety at the edge: the Battery actor enforces physical limits whatever a strategy asks.
9. Contracts are versioned and additive within a major version (`docs/context/08-contracts.md`).
10. Batch jobs (training, backtests, oracle) are CLIs over artefacts with no HTTP surface.
11. No secrets in the repo; required settings fail fast; nothing defaults to a secret.
12. Fixed, pinned tooling (Python ≥ 3.13, uv, ruff, ty, pytest, pre-commit); `make ci` green before merge.
13. Observability is all-or-nothing: end-to-end tracing or none.
14. Reproducibility: every experiment stores config, seed, data window, hardware and git commit.
15. Docs and decisions land with the change: behaviour → `docs/context/`, decision → `docs/adr/`.
16. Measure the system, not just the energy: systems metrics beside energy metrics in every experiment.

## Do not

- Import Restate (or any runtime, I/O or clock) in `src/ems/domain/`.
- Build request-response cycles, or call an exclusive handler with request-response.
- Use wall-clock timers in sim mode, or sleep inside an exclusive handler (use delayed messages).
- Make blocking calls in handlers.
- Add an unpinned dependency, image or tool: everything comes from `uv.lock` or an exact tag + digest
  that is at least two weeks old.
- Commit secrets. `.env` files are unreadable to Claude by design.
- Touch `frontend/` without asking (out of scope; an `ask` rule enforces it).
- Hand-edit experiment results, `docs/bootstrap/`, `reference/`, or Spec Kit-managed files
  (`.claude/skills/speckit-*`, `.specify/scripts/`, `.specify/templates/`).
- Run `helm` or `kubectl` against any context except `kind-ems`: this machine's default kube-context is a
  corporate cluster. Check `kubectl config current-context` first.

## Commits

- Keep commit messages short: one imperative subject line (≤ 72 characters), plus a body of a few lines
  only when the why is not obvious.
- No `Co-Authored-By` or other attribution trailers (also turned off via `attribution` in
  `.claude/settings.json`).
- When a task's code is written, end the reply with a proposed commit message, one per logical change,
  each with the files it covers. Prefix with the spec and task id when there is one (`001/T03: …`).
  Do not run `git commit` unless asked.

## PR description contract

Every PR description states:
- the `docs/context/*.md` files relied on;
- the design principles it touches (by number);
- known issues in scope (`docs/context/09-risks-and-tech-debt.md`), each fixed or "accepted for now";
- contract impact (message schemas, topics, result schemas);
- experiment impact: does a reported number change? If yes, rerun and record it;
- a test plan with at least one new test.
